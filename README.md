# SoundLife 2 (нативное приложение)

Версия 2.23.0 — шаги 3–21 объединения сайта и приложения.

## Что сделано
- Шаг 2: лайки ♥, перемешка, тумблер «поверх других приложений» (шторка + экран блокировки).
- Шаг 3: дизайн под телефон Android и навигация как у Spotify (нижняя панель, мини-плеер, страницы артиста/альбома).
  - AMOLED-чёрный фон, салатовый акцент (#C6FF3D).
  - Нижняя панель: Главная / Поиск / Медиатека; мини-плеер над ней.
  - Главная: приветствие, быстрые плитки (Любимые треки, Перемешать всё, подписки), ряды «Артисты» и «Альбомы», все треки.
  - Поиск: по трекам, артистам и альбомам.
  - Медиатека: «Любимые треки», подписки на артистов и альбомы, фильтр Всё/Альбомы/Артисты.
  - Страницы артиста, альбома и любимых треков с кнопкой «Подписаться»; системная кнопка «Назад» работает.
  - Подписки и лайки хранятся на устройстве.
- Шаг 4: экран плеера как у Spotify (большая обложка, ползунок, кнопки); плейлисты (создать, добавить через ⋮ или кнопку в плеере, удалить); выбор цвета акцента в настройках (5 цветов, сохраняется).
- Шаг 5: музыка из нескольких хранилищ GitHub (GH_REPOS в build.gradle.kts, через запятую); обложки из картинок рядом с треком (cover/folder/artwork.jpg); теги из music/meta.json; дубликаты скрываются, FLAC в приоритете; поиск в iTunes (30-секундные отрывки, без входа).
- Шаг 6: вход в аккаунт Supabase (тот же проект, что у сайта) по почте и паролю; Яндекс Музыка для владельца: полные треки в поиске, воспроизведение через сервис (адрес потока берётся в момент открытия трека).
- Шаг 7: поиск Яндекса показывает исполнителей и альбомы; открываются страницы альбома и исполнителя (треки, альбомы исполнителя, кнопка «Играть»).
- Шаг 8: синхронизация с аккаунтом сайта (таблица user_data): лайки (поле favs, как на сайте), подписки и Яндекс-подписки (свой блок native_subs). Подписка на альбом и исполнителя Яндекса с кнопкой на странице, они появляются в Медиатеке.
- Шаг 9: плейлисты синхронизируются с сайтом (поле pl). Объединяются по названию; совместные плейлисты сайта не трогаем.
- Шаг 10: статистика прослушивания как на сайте (время по трекам, дням и часам, плейлисты, пропуски, запуски, история). Считается в приложении, сохраняется на устройстве и сливается с аккаунтом по максимуму, поэтому часы не сбрасываются. Итог показан в настройках.
- Шаг 12 (вход через Google): кнопка на экране входа открывает браузер; возврат в приложение по адресу soundlife://auth, сессия Supabase из адреса.
- Шаг 13 (тексты песен): кнопка «Текст» в полноэкранном плеере. Сначала свои тексты из music/lyrics.json (как на сайте), потом LRCLIB. Строки с таймкодами подсвечиваются по ходу трека.
- Шаг 14 («Хочу этот трек»): «+» у отрывков iTunes. Список в Медиатеке, пункт «Хочу послушать». Хранится на устройстве и в таблице wishes (ключ it:<id>), как на сайте. Список подтягивается с аккаунта после входа; ссылка на отрывок ищется в iTunes.
- Шаг 15 (Last.fm): в полноэкранном плеере под исполнителем — «Слушателей в мире» и теги. Данные из track.getInfo, кэш в памяти на время работы.
- Шаг 16 (профиль, часть 1): ник и аватарка в настройках, в разделе «Аккаунт». Таблица profiles, как на сайте: ник 3–20 знаков (a–z, 0–9, _ и точка), аватарка 160×160 в data-адресе. Профиль подтягивается после входа и очищается при выходе.
- Шаг 17 (профиль, часть 2): «Найти человека» по нику в Медиатеке; страница человека с кнопкой «Подписаться» и его публичными плейлистами; подписки на людей и публичные плейлисты (таблица follows, kind user / pl) в Медиатеке; публичный плейлист открывается с кнопкой подписки.
- Шаг 18 (сообщения, часть 1): «Сообщения» в Медиатеке (диалоги с непрочитанными), переписка с текстом, отметка о прочтении, реакции (❤️ 👍 😂 🔥 😮 😢: нажать на сообщение, затем на эмодзи), кнопка «Написать» на странице человека. Обновление переписки каждые 4 секунды. Для PATCH добавлен OkHttp.
- Шаг 19 (сообщения, часть 2): голосовые (кнопка микрофона: нажать — запись, нажать ещё раз — отправка; нужен доступ к микрофону), фото (сжимаются до 1600 px) и видео до 25 МБ (скрепка), отправка текущего трека (нота), прослушивание голосовых и открытие видео и видеокружков. Вложения в бакете voice, как на сайте.
- Шаг 20 (совместные плейлисты и «на сайте»): раздел в Медиатеке. Создать совместный плейлист, добавлять текущий трек (кнопка «+ текущий»), убирать треки, смотреть участников. Владелец добавляет и убирает участников, переименовывает и удаляет плейлист; участник может выйти. Хранится на сервере (collab_*), как на сайте. Для «Хочу послушать»: если трек уже есть в библиотеке, играется полная версия, и в заголовке виден счёт «на сайте».
- Шаг 21 (настройки и публичные плейлисты): акцентный цвет берётся с сайта (поле set, только чтение: сам сайт и его настройки не меняются); светлые темы сайта не переносятся. В экране плейлиста кнопка «Сделать публичным»: плейлист виден в public_playlists, треки обновляются при открытии.
- Шаг 11: поиск по трекам понимает раскладку (ghbdtn → привет), транслит (privet → привет) и опечатки.

## Как собрать
**Вариант A (Android Studio):** File → Open → папка SoundLife2 → Run.
**Вариант B (без ПК):** залей папку в новый репозиторий GitHub → вкладка Actions → Build APK → скачай APK из Artifacts.

Хранилища с музыкой меняются в app/build.gradle.kts (GH_REPOS, через запятую).

## Настройка входа (один раз)
1. Supabase → Authentication → URL Configuration → Redirect URLs: добавить `soundlife://auth`. Google-провайдер уже включён для сайта.

## Шаг 22 (версия 2.20.0)
- Вход на компьютере по QR: сканируется QR с сайта, после подтверждения вызывается clever-function (approve) с токеном пользователя. Файл QrLogin.kt, кнопка в настройках аккаунта.
- Видеокружки: запись фронтальной камерой (CameraX), пока удерживаешь кнопку, до 60 с, отправка в чат как ⭕ Видеокружок. Файл Circle.kt, кнопка в чате.
- Светлые темы: Palette (Ui.kt) пересчитывает цвета из фона сайта (user_data.set.v.bg), акцент тоже с сайта (acc). Фон сохраняется в настройках.
- Зависимости: zxing-android-embedded 4.3.0, CameraX 1.3.4. Разрешение CAMERA в манифесте.

## Шаг 23 (версия 2.21.0)
- Уведомления о сообщениях без Firebase: WorkManager раз в 15 минут проверяет непрочитанные сообщения (messages, recipient = я, read_at пуст) и показывает уведомление. Текст сообщения не показывается. Файл Notifier.kt.
- Разрешение POST_NOTIFICATIONS запрашивается при запуске (Android 13+).

## Шаг 24 (версия 2.22.0)
- Realtime-клиент (Realtime.kt): Supabase Realtime по websocket, broadcast, переподключение, обновление токена раз в 50 минут.
- Звонки (Calls.kt, CallUi.kt): как на сайте, сигналы через канал sl-call-<uid>, сама связь через VDO.Ninja в WebView. Кнопки звонка и видеозвонка в шапке чата. Запись звонка в чат (call/<id>/<итог>).
- Входящие звонки: фоновый сервис CallService держит соединение (тихое уведомление «На связи»), входящий показывается полноэкранным уведомлением.
- Вызов сразу проверяет разрешения на микрофон и камеру.
- Ограничение: Android 15 останавливает такие фоновые сервисы примерно через 6 часов. Соединение поднимется снова при открытии приложения.

## Шаг 25 (версия 2.23.0)
- «Слушаем вместе» (Jam.kt): создать комнату, войти по коду, позвать друга (системное «Поделиться»), выйти. Комната — канал sl-jam-<код>, формат сообщений как на сайте (st, hi), поэтому приложение и сайт могут слушать вместе.
- Состояние трека передаётся каждые 5 секунд и при каждом изменении (трек, пауза, перемотка).
- Трек играет только если он есть в библиотеке приложения.
- Количество участников не показывается.
